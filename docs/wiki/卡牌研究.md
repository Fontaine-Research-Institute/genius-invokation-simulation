# 卡牌研究

> 中文 · [[卡牌研究-EN|English]]

*本页范围: 卡牌研究栏目说明 (贴描述 + 实现代码 + 实测) , 写作要求, 页面模板, 已研究条目, 依据与维护约定.*

---

## 1. 这个栏目是什么

**卡牌研究** = **贴描述 + 实现代码 (+ 实测) **: 针对一张具体卡, 把卡面文字, 我们的实现代码与实测记录放在同一页, 便于复核与对照.

| 项 | 说明 |
|---|---|
| 研究对象 | 一张具体卡 (角色 / 行动牌 / 召唤物 / 状态等)  |
| 内容 | 卡面描述 (中 / 英 + 关键字展开) → 完整实现代码 (真实源码) → 实测记录 → 备注 |
| 不写什么 | 不写外部数据路径 / 来源标注, 不写卡牌数字编号, 不写长篇'交互链逐步序列' |
| 未实现的卡 | 实现代码一节贴**计划中的完整代码**并标 `[!WARNING] 未实现`, 同时按能力列出'还缺什么' |

> [!IMPORTANT]
> 描述概括卡面内容, 代码贴全文: 描述用我们自己的话概括卡面内容; 实现代码整段贴出 (连 `use` / 常量 / 测试等样板也不省略) , 不节选关键行.

## 2. 写作要求

### 2.1 固定 4 节

| 节 | 必须写什么 |
|---|---|
| `## 1. 卡面描述` | 中文 / 英文描述 (技能 / 模式用三行式); 关键字展开 (关键字名称 → 说明) ; 相关规则书条目摘录 |
| `## 2. 实现代码` | **完整**实现代码 (真实源码, 标文件路径, 不节选) ; 未实现时贴计划中的完整代码 + `[!WARNING] 未实现` + 按能力列缺口 |
| `## 3. 实测` | 表: `项目 / 局面/操作 / 游戏内结果 / 我们的实现结果 / 结论`; 未测写'待实测'并给可复现操作步骤 |
| `## 4. 备注` (可选)  | 坑 / 相关 D 编号 / 关联页面 |

### 2.2 写作硬规

| 编号 | 规则 |
|---|---|
| 1 | **不写外部数据路径与来源标注**: 不写磁盘路径, JSON 文件名, 生成目录名, 也不写语言来源标注; 只写卡面文字本身 |
| 2 | **不写卡牌数字编号**: 不写天赋 / 状态 / 角色 / 事件 / 召唤物的数字 id, 一律用**名称**叙述 |
| 3 | **`§1.1` 不写用户点名要删的那个措辞** (见任务说明, 不要在正文复述它)  |
| 4 | **元信息逐行写**: 类型, 标签, 费用等每项单独一行 (或列表逐行) , 不要一行里堆多项 |
| 5 | **实现代码贴在原处**: 讲到哪段能力, 就紧跟着贴那段真实源码; 不要集中堆到页尾 / 最后一节, 也不要只给链接 |
| 6 | 无 emoji; 表格带对齐行; 关键提醒用 `[!NOTE]` / `[!IMPORTANT]` / `[!WARNING]` |
| 7 | 代码块标 `rust` (命令 `bash`, 配置 `toml`) ; 源码与当前仓库一致, 接口改动要重贴 |
| 8 | 页尾: `---` + `最后核对: YYYY-MM-DD (代码: <文件>:<符号>)` |
| 9 | **只用半角标点**: 逗号 / 句号 / 冒号 / 分号 / 叹号 / 问号 / 括号 / 方括号 / 引号 / 尖括号 / 连字符; 不得出现全角标点 |
| 10 | **描述照抄卡面文字**: 保留原标点; 引用块是唯一保留全角标点的地方 (我们自己的话仍用半角) |
| 11 | **不写关键字编号**: 关键字编号也是 ID; 用关键字名称 (充能 / 物理伤害 / 可用次数 / 秘传 / 不可发现等) 或一句说明代替 |
| 12 | **形态不合并**: 始基力：荒性形态与始基力：芒性形态各一张表, 名称写全称 |
| 13 | **被动技能不列费用**: 没有费用字段, 不写表示无费用的行, 直接不列 |
| 14 | **技能不用表格**: 每个技能三行式: 技能名 / 技能种类 (普通攻击 / 元素战技 / 元素爆发 / 被动技能 / 天赋, 不加种类前缀) / '>' 照抄卡面描述; 被动不列费用, 费用单独一行 |
| 15 | **代码块注释**中的关键字编号替换为名称, 并在代码块上方加一行注记; 代码行保持仓库原样 |
| 16 | **费用行完整写法**: 禁止简写; 用 'x 个水元素骰 + n 个任意元素骰 / n 个相同元素骰'; 骰子费用与充能分行; 无充能不写 0; 被动整行省略 |

依据顺序: 规则书 > 卡面 / 权威关键字 > 参考实现 (参考实现只看方法, `RULES.md` 第三节第 2, 3 条) .

## 6. 维护约定

- **代码变了就重贴**: §2 的源码块来自仓库; 实现改动后重贴并更新页脚.
- **新卡**: 模板 + §4 表格一行; 中文页 `卡牌研究-<名称>.md`, 英文页 `卡牌研究-<名称>-EN.md`.
- **实测结果**只能写: 一致 / 不一致 / 待实测; 不一致要写清差异 (如标点, 数值) .
- **顺序结论**: 一句话 + 可复现步骤写进 §3, 依据补进 §4.2 D 编号; 不展开成长篇交互链.
- `_Sidebar.md` / `_Footer.md` 由维护者统一维护.
