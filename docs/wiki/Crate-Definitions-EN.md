# Crate-Definitions (Game Definition Layer)

> [[Crate-Definitions|中文]] · English

*Scope: the `definitions` crate's responsibility, directory and concepts, public entry points and features, invariants, basis, test scale, and pending work.*

---

## 1. Responsibility (What This Layer Solves)

Holds every game definition except concrete cards: families / types / tags, spent resources (dice pool), unified three-level base operations, state and chained flows, keywords and steps, trigger dispatch, elemental reactions, unified records, compile-time source embedding, version sync, and the data plus rich-text rendering generated by `build.rs`.

- Directory: `new/crates/definitions/`
- package / lib: `gi-genius-invokation-definitions` / `gi_genius_invokation_definitions`
- Depends on: `engine` (mechanism primitives), `richtext` (text parsing); zero third-party dependencies by default
- Excludes concrete cards (D240 / D241): those live in `cards` and are optional through the `simulation` facade (D243)

## 2. Key Concepts and Types

Layering (D51 / D53 / D54): base (L1 families + ids + elements + perspective) -> families (L2 type enums + definition carriers + areas + operations) -> tags (L3 tags, a top-level directory).

- `src/base/`: `CardFamily` (id regions) + `CardId` / `SkillId` / `Element` / `Perspective`
- `src/families/`: Per-family framework: type enums + definition carriers + area state + low-level operations (action cards: support area / hand-card statuses / current cost / pile / queries; characters: damage / damage modifier chain / skill flow / forms and growth / equipment slots / status areas; summons: definition + summon area; statuses: type enum + definitions; enemies: definition)
- `src/tags/`: L3 tags: top-level, grouped by family/type; one tag = one file = one zero-sized type (D54), 52 in total
- `src/resources/`: Spent resources: `dice/` pool — pure counts (not entities, D47), three-part representation (D49), generation / payment / conversion / queries / folding and expansion
- `src/rules/`: Unified three-level base operations: `RuleRow` static rule table + `ops/` pure functions (slots / caps / opening / food / damage / queries / order; self-playing cards excluded)
- `src/timeline/`: Trigger/event dispatch: generic registry (timing key + condition fn pointer + effect fn pointer, D186) + ordered dispatch + settlement frames (D196)
- `src/reactions/`: 14 elemental reaction identities (11 base + 3 lunar) + effect fn pointer table + effect requests (`EffectOp`)
- `src/records/`: Unified recorder `Record<T>` / `Recorder<T>` / `ShowRecord` (D222-D225)
- `src/source/`: Compile-time source embedding: `card_source!` / `module_source!`, `SourceFile` / `SourceOwner`, use-dependency parsing (D210-D216 / D242)
- `src/version/`: `GameVersion` + `card_game_version!` (D244-D246)
- `src/generated/`: `build.rs`-generated data tables + accessors + `Localized` (D56) + rich-text `render` (parsing comes from richtext)
- `src/state/`: `DefState` (`me` / `opp` + `round` + `first_player`) / `PlayerDefs` + game-over detection + `state::flows` (opening / switch / defeat / revive / end phase / round begin / plunging marker)
- `src/flow/`: End-to-end action entries: skill use / card play / character switch / elemental tuning / techniques / round skeleton / `pending` executor / `recorded` wrappers / hooks
- `src/keywords/`: Keyword functions + Step (D204) + target selectors (including self, D205 / D206) + reaction sub-settlement + `trace` / `record`

**Data tables**: generated data is read at compile time by `build.rs` into static tables, with no runtime file IO; tag data is field access via `generated::TAGS.<field>` (D67).

## 3. Public Entry Points

All modules are `pub`: `base` / `families` / `flow` / `generated` / `keywords` / `reactions` / `records` / `resources` / `rules` / `source` / `state` / `tags` / `timeline` / `version`. The crate root has no `pub use`; external users go through the `simulation` facade. The crate root exports three macros:

- `card_source!(path: ["character", "aino"])`: Card-file source self-declaration (binds the module's `pub const ID` automatically, D215)
- `module_source!(path: [...], name: MODULE_NAME)`: Non-card module source self-declaration plus a multilingual name
- `card_game_version!(6, 2)`: Declares the latest game version this card has been synced to (D244-D246)

**Main public types / entries**

- `state`: `DefState::new / from_players`, `DefState::{me, opp, round, first_player}`, `state::flows::*`, `state::terminal::{settlement_outcome, Outcome, ROUND_LIMIT}`
- `flow`: `use_skill_me/opp`, `play_card_*` (including `_with_timing` / `_food` / `_arcane`), `switch_character_*`, `tuning_*`, `use_technique_*`, `turn::*`, `pending::{execute_pending, execute_frames}`, `recorded::*`, `fold_states`
- `keywords`: `Step`, `execute_step_me/opp`, `execute_steps_*`, keyword functions (`cause_damage` / `heal` / `apply_status` / `summon` / `draw_cards` / `gain_dice` / ...), `TargetSelector`
- `timeline`: `TriggerRegistry` / `Trigger` / `dispatch` / `resolve` / `Resolution` (frames + `insert` / `snapshot`)
- `records`: `Recorder<T>` / `Record<T>` / `ShowRecord`
- `rules`: `rows()` / `RuleRow` / `ops::*` pure functions
- `resources::dice`: `DicePool` / `DieFace` / `CostComponent` / `DiceGenSpec` / `can_afford` / `pay` / `all_dice`
- `source`: `SourceFile` / `SourceOwner` / `source_files()` / `source_of(path)`
- `version`: `GameVersion`; `version::Nat` re-exports engine's `Nat`

**Cargo features**

- `embed-source`
  - Default: yes
  - Meaning: compile-time source embedding (D213); when off, `SOURCE.content` is empty and the summary table is empty
- `records`
  - Default: yes
  - Meaning: unified recorder (D223 / D224); when off, `Recorder` is zero-sized and `push` is a no-op
- `stats`
  - Default: no
  - Meaning: per-block `stats/` counters (D187); when off they become no-ops
- `rules`
  - Default: no
  - Meaning: enables `engine/rules` and compiles the `GameRules` adapter (`state/terminal.rs`, D24)

```rust
/// 卡牌文件宏（D214 / D215 / D216 / D242）。
///
/// 用法（在卡牌 crate 里）：gi_genius_invokation_definitions::card_source!(path: ["character", "aino"]);
///
/// - 具体卡牌在 gi-genius-invokation-cards crate（D240 / D241）；本宏是**通用定义**，留在本 crate；
/// - 路径是**分段字符串列表**（每段一个 "..."，内部用 / 拼接）；
/// - 拼出 src/cards/<segments...>/mod.rs；include_str! 以**调用方 crate** 的
///   CARGO_MANIFEST_DIR 为根（从 cards crate 调用时读到 crates/cards/src/cards/...），
///   path 字段仍是 src/cards/...（结构不变）；
/// - **不写 id**：展开直接引用本模块的 pub const ID: CardId。本模块没有 ID
///   （或类型不是 CardId）时，展开里的 const _: CardId = ID; 会**编译报错**，
///   提示「本模块需定义 pub const ID: CardId」，不会静默绑定错 id。
#[cfg(feature = "embed-source")]
#[macro_export]
macro_rules! card_source {
    (path: [$($segment:literal),+ $(,)?] $(,)?) => {
        /// 本文件的归属 + 编译期嵌入的原文 + 解析出的依赖（D213 / D214 / D215 / D216）。
        pub static SOURCE: $crate::source::SourceFile = {
            // D215：宏里不写 id —— 绑定本模块的 pub const ID: CardId；
            // 本模块缺 ID 或类型不对时这里编译报错（不静默）。
            // 本模块需定义 pub const ID: CardId。
            const _: $crate::base::CardId = ID;
            const CONTENT: &str = include_str!(concat!(
                env!("CARGO_MANIFEST_DIR"),
                "/",
                concat!("src/cards", $("/", $segment),+, "/mod.rs")
            ));
            $crate::source::SourceFile {
                // D215：id 自动绑定到本模块的 ID（调用处解析，不重复写卡 id）。
                owner: $crate::source::SourceOwner::Card(ID),
                path: concat!("src/cards", $("/", $segment),+, "/mod.rs"),
                segments: &[$($segment),+],
                content: CONTENT,
                dependencies: $crate::source::parse_dependencies(CONTENT),
            }
        };
    };
}
```

```rust
/// 声明「本卡 / 本模块已同步（核对）到的最新游戏版本」（D245 / D246）。
///
/// 用法：crate::card_game_version!(6, 2); 生成
/// pub const GAME_VERSION: GameVersion = GameVersion::new(Nat::new(6), Nat::new(2));
///
/// 语义（D245 / D246）：
/// - 这个值 = 本卡已同步（核对）到的最新游戏版本；
/// - 「已同步到最新版本」的唯一表示方式 = 把宏里的版本号改成最新版本号；
/// - 不要求卡牌内容有任何改动：新版本没调整这张卡，同样算同步（未调整也算同步）；
/// - 卡牌实现与版本数值解耦：数值只表示「核对过，且该卡在该版本未调整」。
///
/// 升级流程（D246）：**改数字 -> 不动卡牌内容**。
/// 例：最新版变成 6.3 时，把 crate::card_game_version!(6, 2); 改成
/// crate::card_game_version!(6, 3);，卡牌实现保持原样即算已同步。
#[macro_export]

        /// 本卡 / 本模块已同步（核对）到的最新游戏版本（D245 / D246；由 card_game_version! 生成）。
        pub const GAME_VERSION: $crate::version::GameVersion = $crate::version::GameVersion::new(
            $crate::version::Nat::new($major),
            $crate::version::Nat::new($minor),
        );
    };
}
```

```rust
/// **单侧派发**：从一个牌手的注册表里取出「这个时机、条件成立」的登记项，按结算顺序排好。
///
/// 排序 = `结算顺序.md` §一 第 2~4 条：来源类别 -> 进场先后 -> 登记顺序（稳定排序）。
/// 第 1 条「当前牌手优先」不在本函数里：它由 [`resolve`] 用「两个注册表的先后」表达。
///
/// 只读 + 不执行：不调用任何效果函数指针，也不改注册表。
#[must_use]
pub fn dispatch<'e, K, E>(
    registry: &TriggerRegistry<K, E>,
    timing: K,
    event: &'e Event,
) -> Vec<Pending<'e, E>>
where
    K: Copy + PartialEq,
    E: Copy,
{
    // 1) 只留「时机相等 + 条件成立」的登记项。
    let mut matched: Vec<Trigger<K, E>> = registry
        .entries()
        .iter()
        .copied()
        .filter(|trigger| trigger.applies(timing, event))
        .collect();
    // 2) 按结算顺序排（稳定排序：完全同序时保持登记顺序）。
    matched.sort_by(by_resolution_order);
    // 3) 产出「函数指针 + 事件」的待执行列表（不执行）。
    matched
        .into_iter()
        .map(|trigger| Pending {
            effect: trigger.effect,
            event,
            owner: trigger.owner,
            source_kind: trigger.source_kind,
            entry: trigger.entry,
        })
        .collect()
```

File: crates/definitions/src/resources/dice/mod.rs:649-698

```rust
    /// 够不够付（**可能就行**，D144）：折叠组按「可能是什么色」计入上界。
    ///
    /// 注意：pay 要求折叠组先展开，所以 can_afford = true 不保证 pay 直接成功。
    pub fn can_afford(&self, cost: &[CostComponent]) -> bool {
        validate_cost(cost);
        let mut demand = [Nat::ZERO; 7];
        let mut any = Nat::ZERO;
        let mut same_color_counts: Vec<Nat> = Vec::new();
        for component in cost {
            match *component {
                CostComponent::SpecificElement(element, count) => {
                    let slot = element_slot(element).get() as usize; // bare-int-ok: 容器下标
                    demand[slot] = nadd!(demand[slot], count);
                }
                CostComponent::AnyColor(count) => any = nadd!(any, count),
                CostComponent::SameColor(count) => same_color_counts.push(count),
            }
        }
        for count in same_color_counts {
            let mut best_slot = Nat::ZERO;
            let mut best_delta: Option<Nat> = None;
            for (slot, element) in ELEMENTS.iter().enumerate() {
                let known = known_count(&self.known, *element);
                let current = demand[slot];
                let before = shortfall(current, known);
                let after = shortfall(nadd!(current, count), known);
                let delta = nsub!(after, before);
                if best_delta.is_none_or(|best| delta < best) {
                    best_delta = Some(delta);
                    best_slot = Nat::new(slot as _);
                }
            }
            let slot = best_slot.get() as usize; // bare-int-ok: 容器下标
            demand[slot] = nadd!(demand[slot], count);
        }
        let mut demand_total = any;
        for count in demand.iter() {
            demand_total = nadd!(demand_total, *count);
        }
        if demand_total > self.total() {
            return false;
        }
        let flexible = nadd!(self.omni, folded_total(&self.folded));
        let mut shortfall_total = Nat::ZERO;
        for (slot, element) in ELEMENTS.iter().enumerate() {
            let known = known_count(&self.known, *element);
            shortfall_total = nadd!(shortfall_total, shortfall(demand[slot], known));
        }
        shortfall_total <= flexible
    }
```

```rust
    /// 扣减（确定性，不产生分支；D47/D144）。付不起 -> None。
    ///
    /// - 按 ① SpecificElement → ② SameColor → ③ AnyColor 顺序扣（D168/D169）；
    /// - SpecificElement：先用该色的 known，再用万能；
    /// - SameColor：付哪个颜色由调用方给（same_color）；没给 -> None；
    /// - AnyColor：按固定顺序扣「折叠组 -> 具体色（元素序）-> 万能」（不产生分支）。
    ///
    /// 折叠组未显式展开时不能用于指定色 / 同色（返回 None）。
    pub fn pay(&self, cost: &[CostComponent], same_color: Option<Element>) -> Option<DicePool> {
        validate_cost(cost);
        let mut next = self.clone();
        // ① 指定元素骰
        for component in cost {
            if let CostComponent::SpecificElement(element, count) = *component {
                next = next.pay_color(element, count)?;
            }
        }
        // ② 相同元素骰（颜色由调用方给）
        for component in cost {
            if let CostComponent::SameColor(count) = *component {
                let element = same_color?;
                next = next.pay_color(element, count)?;
            }
        }
        // ③ 任意元素骰
        for component in cost {
            if let CostComponent::AnyColor(count) = *component {
                next = next.pay_any(count)?;
            }
        }
        Some(next)
    }
```

## 4. Invariants and Prohibitions

> [!IMPORTANT]
> This crate holds no concrete cards and has a one-way dependency (it must not depend on `cards` / `simulation`). Public entries are pure: take `&DefState` and return a new state; inputs are never mutated.

- Zero `f64` (D159): probabilities and weights are `Fraction` (`ExactNat128`); business numbers are `Nat`.
- No bare integers or bare arithmetic (section 8.3): `#![deny(clippy::arithmetic_side_effects)]` plus three advisory scanners.
- Single source of data: tag data lives only in `generated::TAGS` (D64 / D67); source macros and types live only here (D242); `CostComponent` lives only in `resources::dice` (D161).
- Sides are not numbered; areas are variables (D29 / D34 / D42); paired entries share one implementation.
- A step is atomic (D204): no insertion inside a step; insertion only between steps.
- Settlement is insertion-based, not a stack (D196); the settlement order authority is `结算顺序.md`, with constants only in `rules::ops::order`.
- Do not materialize uncertainty up front (D190 / D191): expand at observation points into branches with exact probabilities, then fold back.
- Disabling features never changes semantics (`records` / `stats` / `embed-source`).
- No global state: registries, recorders, and dice pools are plain value fields.

## 6. Common Misuse

> [!WARNING]
> Do not write concrete cards here, do not use `f64` or bare arithmetic, do not rebuild tag enums or numeric tag ids, and do not execute effects inside `timeline::dispatch`.

- Letting `definitions` depend on `cards` / `simulation` (reverse dependency; cards has a guard test).
- Inserting a sub-settlement inside a step (violates D204).
- Writing a second settlement-order table (the single authority is `结算顺序.md`).
- Defining business fields or kind enums inside `records` (content types belong to modules, D225).
- Letting disabled `records` / `stats` change settlement results.
- Adding a module file with `module_source!` but forgetting its line in `source::SOURCE_FILES` (compiles, but `source_of` cannot find it).
