# 写作风格

> 中文 · [[写作风格-EN|English]]

*本页范围: 本 Wiki 的文风规范, 参照 Rust 官方教程的写法.*

---

## 1. 核心: 代码与文字交叉

教程的写法是**一段话, 一段代码, 再一段话**, 而不是先讲一大段再贴一大块代码. 每段代码前一句说明这段要解决什么, 代码后一句说明它为什么这样写, 下一步还要做什么.

代码块上方标出文件位置, 用代码块上一行的普通文字写 `文件: crates/.../mod.rs`, 不要塞进代码块里当注释.

### 例子

角色定义只需要给出一份静态数据, 引擎按它建角色. 先看结构:

文件: crates/definitions/src/families/character/def.rs

```rust
pub struct CharacterDef<Tags> {
    pub id: CardId,
    pub name: Localized,
    pub max_hp: Nat,
    pub max_energy: Nat,
    pub tags: Tags,
}
```

`max_hp` 与 `max_energy` 是角色上限, 状态里另存当前值, 二者不要混用.

角色牌自己的静态定义只填这份数据, 不带行为:

文件: crates/cards/src/cards/character/aino/mod.rs

```rust
pub static AINO: CharacterDef<Tags> = CharacterDef { ... };
```

行为写在技能效果函数里, 由技能定义引用. 下一个代码块是技能的静态定义, 里面只挂函数指针, 不做计算.

## 2. 段落

一句话一件事, 一段 1-3 句. 不要出现 5 句以上的长段.

## 3. 章节

每页固定 8 节, 编号从 1 开始:

1. 职责 (这一层解决什么问题)
2. 关键概念与类型
3. 公开入口
4. 不变量与禁止
5. 依据 (规则书条款 / 决策编号)
6. 常见误用
7. 测试在哪
8. 待接入与待实测

每页结尾必须加 `## 小结`, 用 2-3 句回顾这一页最重要的结论.

## 4. 不用表格

**全站禁止表格**. 需要并列对照时用列表, 需要讲接口时用"一段文字 + 一段代码".

例如三个区域不要排成表, 而是:

- 角色区: 三个槽位加一个出战指针;
- 装备区: 每个角色一排;
- 出战状态区: 整侧共用.

## 5. 提示块

> [!NOTE]
> 背景与延伸阅读.

> [!WARNING]
> 禁止做法与易错点.

## 6. 术语

第一次出现给中英文与定义, 之后只用中文.

## 7. 不要写的东西

不写卡牌编号, 不写裸关键字编号 (改成关键字页链接), 不写数据文件路径, 不写逐步结算大表.

## 9. 小结

短句, 先例子后解释, 代码与文字交替, 每节都有结论. 写完自己读一遍: 一个没看过代码的人能不能顺着读懂.
