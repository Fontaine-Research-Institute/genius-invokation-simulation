# genius-invokation-simulation

**简体中文** | [English](README.en.md)

**粉丝自制的七圣召唤（Genius Invokation TCG）模拟 —— 规则引擎 · 对局模拟 · 精确概率求解，Rust 实现。**

本项目把随机**保留成分支与概率**，因此能算出**精确概率**（首回合击杀 FTK 只是其中一个用例）。

## 项目理念

> **谁要什么功能，框架就给他一个功能接口，他自己去干。**

这条压过一切具体设计：

1. **框架不做中枢统计、不做中枢收集、不做内建行为表** —— 只提供接口与原语。
2. **具体功能谁要谁实现**：卡牌、牌族、具体 tag 自己写。
3. **同类功能归同一个「统一包装」层**（例如「技能类行为」统一包装在角色牌族里）。
4. **框架负责「能不能」，卡牌负责「做什么」。**

换句话说：框架把「判断权」交回给具体的卡与牌族，自己只管把状态、随机、选择、加载、文案这些**基础设施**做对。

同源的几条坚持：引擎零游戏语义；随机与选择都走单一枚举入口（所以概率精确）；**不同历史不进同一哈希**；**未展示的信息一律当未知**。

## 它能做什么

| 能力 | 说明 |
|---|---|
| **规则引擎** | 完整结算七圣召唤规则；卡牌效果全部由 `definitions` 层实现 |
| **对局模拟** | 用策略把整局跑完：验证卡牌、回归测试、生成复盘 |
| **多回合决策** | 在博弈树上做 expectimax：我方 MAX / 敌方 MIN / 随机 CHANCE，可算若干回合内的胜负与期望 |
| **精确概率** | 精确枚举 + 多重集折叠；结果精确，同一局面可复现 |

## 核心设计

### 引擎 = 纯数据层

引擎只知道三样东西：

1. **实体**（`EntityId`）—— 一个数值句柄
2. **容器** —— 两种：多实体容器、单实体容器（= 一个变量）。**区不是编号**，就是上层自己持有的变量，编译后直接寻址
3. **随机 / 选择**（两个纯函数）—— `enumerate_random` / `enumerate_select`，所有随机与选择都必须走它们

引擎**不知道**什么是召唤物、支援牌、弃置、伤害、元素反应、费用 —— 它眼里只有"实体"和"区"。

### 万物皆实体

一颗骰子、一张牌、一个召唤物、一个支援、一个角色 —— 全都是实体。区同样是开放的：

```
手牌 / 牌库 / 支援区 / 召唤物区 / 场上角色 / 骰池 / 每个角色各自的装备栏
```

### 卡牌是 Rust 代码

卡牌就是 Rust 函数：同一门语言、同一套类型系统、同一个调试器。

### 类型树 = 文件夹树

`行动牌 → 支援 / 装备 / 事件` 的类型关系直接对应目录结构，支持**全路径**（`行动牌.支援.场地`）与父级标签继承。

### 敌我：两个根区，不传参数

引擎**不分敌我**，也不给区编号：区就是上层自己持有的变量。"一个「人」"就是**一套模块实例**，
各模块自己持有自己的容器（手牌 / 牌库 / 骰池 / 召唤物区 / 每个角色的装备栏…）：

```text
root_me  = group 区 ── hand_me / pile_me / dice_me / summons_me / …
root_opp = group 区 ── hand_opp / pile_opp / dice_opp / summons_opp / …
```

上层不传 side 参数，而是**成对入口**：`hand_me()` / `hand_opp()`、`draw_me()` / `draw_opp()` —— 一层转发到共用实现，规则只有一份。

## 特性清单

### 牌库与随机

- **分段牌库表**：随机段（无序，O(1) 抽取）+ 固定段（有序），段序列可变长，不设容量上限
- **同源随机池**：拆开的随机段用**下标指针共享同一份随机内容**，抽走一张只需在池里删一次
- **任意位置随机舍弃**：可从整副牌库任何位置随机取牌舍弃
- 抓牌支持：按段抓 / 按类型抽最上面 / 按卡牌 id 定位 / 一次抓 N 张（不够则少给）
- **抓牌**溢出：抓到的这张**弃置**；**加入手牌/生成卡牌**溢出：**不允许加入**（加不进的牌不会展示，无法确定是哪张）

### 骰子

- **每颗骰子 = 一个独立实体**（带面），骰池是实体区；总量 0~16
- **创建**：`DiceGenSpec { count, distinct, base, element }` —— 可动态数量、是否不重复、是否全同、限定元素
- **扣除**：使用元素骰费用格式（同色 / 任意色 / 指定色）

### 费用与支付

- `cost` 只是**花费属性**（我"要花什么"）
- **当前状态与支付**在**被花的东西**那边：骰池、秘传揭令、充能
- 费用数据挂在卡牌定义里（`ActionCardDef.cost`），支付逻辑随对应资源走

### 支援 / 召唤物 / 状态

- 支援区：上限 4、**有顺序**；满时**由玩家选择**弃哪张；支援的"值"是**布尔 / 计数二选一**（互斥）
- 召唤物区：上限 4，满时无法召唤但动作算发生；三项属性（次数 / 效果类型 / 效果量）**全部可选**；同名再召唤时**次数与效果量取最大、效果类型取最新**
- 状态：战斗状态 / 角色状态两种挂载点；**不叠加**，同状态**高次数覆盖低次数**
- **舍弃** = 从牌库/手牌中移除；**弃置** = 支援区、召唤物区等其它移除，以及**抓牌溢出**（视作弃置此牌）

### 角色与装备

- 我方 2~4 名角色、敌方 1~无上限，场上最多 4 名；不足时从后台填补
- 伤害类操作挂在"角色"上（血量是角色的属性）
- 装备 = **特殊行动牌**；**每个场上角色各挂一个实体区**（= 它的装备栏）；武器按武器类型匹配、圣遗物谁都能装、天赋不互斥

### 结算与反应

- **结算顺序**：各类型自己登记「在谁之前 / 之后」，**编译期**解出唯一全序（不存内置顺序表、不设固定槽位）
- **元素反应**：每种反应一个定义（触发条件 + 效果 + 优先级），**可覆写**（A 的触发 → B 的效果）

### 精确求解

- 随机保留为**分支 + 概率**，因此结果精确、可复现
- 三类节点：我方 **MAX** / 敌方 **MIN** / 随机 **CHANCE**
- 记忆化 + 置换表 + 剪枝；置换表的键是**完整状态**——**不同历史不进同一哈希**（不做跨路径归并）
- 对局模拟与搜索**解耦**：模拟不需要搜索，搜索可以在任意深度停下来用估值

### 可扩展与可复现

- 卡牌通过 **dll 动态加载**，默认全部编进一个 dll（支持拆多）
- 每个卡牌 dll 记录框架 dll 的 **sha256** 与 **ABI**（rustc release + commit），不匹配则拒绝加载
- **两阶段加载**：注册 → 封印 → 查询；每加载一个 dll 后重算统计表
- 随机状态存在状态里、随调用传入传出 ⇒ 同一局面可复现
- 中英双语术语（缺该语言时**显式报告回退**）

### 性能

- `Nat(u32)` 饱和整数、零拷贝（`&T` / `&str` / `&[T]`）、`Rc` 结构共享、位打包
- 求解器后续接入 Zobrist 哈希与置换表
